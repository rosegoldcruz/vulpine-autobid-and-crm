# Engine application principal

Create a dedicated nologin host user. Record its actual UID/GID in ENGINE_API_UID and ENGINE_API_GID and configure a securely generated URL-safe ENGINE_DB_PASSWORD with ENGINE_DB_USER=vulpine_engine_app in private .env. Run `python3 db/provision-api.py` before starting api. Existing administrator credentials are preserved. The utility permits public application CRUD and sequence use, grants no DDL or unrelated schema access, and writes root-only 0600 .env.api from the application's Settings fields. Docker injects this restricted environment; unrelated administrator credentials must not reach the application.

Build images from a context excluding environment files, version-control metadata, uploads and local runtime artifacts. Use reviewed, versioned dependency requirements and verify the resulting installed inventory. Source mounts are read-only; only uploads is writable by the application UID. Before deployment, verify an isolated instance under the configured UID, database-connected health, authenticated CRUD inside a rolled-back transaction, nonadmin role flags, unrelated database/schema denials and protected API authentication behavior. Resource policies are explicit: one GiB, two CPUs and 128 tasks. Validate workload capacity before raising them.

Browser automation requires a separately provisioned read-only browser cache accessible to the service user. Verify browser startup and authenticated integration behavior before enabling those workflows. Recovery requires private environment, database and deployment-configuration backups plus a verified image. Restore to an isolated target and verify application contracts before switching production.
