# Security baseline and release checks

The legacy engine API requires an approved authentication and webhook-signature contract before its business routes can be enabled. Until that contract is configured and verified, business routes reject requests before handlers run. Health endpoints remain available. The legacy AI project-create proxy also rejects writes until its caller authentication contract is configured. Do not replace these gates with host-header, loopback, or arbitrary provider-key checks.

Tracker API access requires the configured integration key, including local requests. Operations must use that same existing integration credential through its restricted runtime environment. Public health remains available. Tracker uploads validate PDF content, file size, and multipart limits before archival.

The backoffice uses its existing session roles/capabilities. Vision additionally scopes project access to the authenticated organization. Shared document/tracker stores require an explicitly approved organizational access policy; application capabilities alone do not establish tenant ownership.

Production dependencies and lockfiles are reviewed together. Vendor preview bundles are copied assets and excluded from application lint, rather than editing third-party distribution files. Keep scanner output, host inventories, credential incident details, runtime environments, and backups outside this public repository.

For changes, run the smallest relevant regression suite, then workspace tests, lint/typecheck, and build. Stage a complete release, exercise unauthorized and authorized requests with test data, and switch traffic only after verification. Avoid live customer notifications, paid AI requests, or customer record creation during negative smoke tests. Keep the prior verified release/configuration for rollback.

For an incident, identify the affected route/service and contain its ingress or operation; preserve private evidence; replace confirmed exposed credentials with operator approval; update all consumers; verify legitimate use; revoke old credentials; check rejection; document the outcome. Never print tokens, private keys, passwords, connection strings, provider response bodies, or submitted customer records.

Documents and legacy Drive require `SFTP_HOST_KEY_SHA256`, an OpenSSH `SHA256:` fingerprint from established trusted provider host-key material. Missing/invalid pins fail before connecting; a mismatch rejects the SSH handshake before authentication. Runtime provisioning must use each service's restricted environment. Changing the pin requires verifying the provider's new host key; do not enroll a key solely because a new network scan returned it.

Documents bounds aggregate multipart file bytes with `DRIVE_UPLOAD_MAX_BYTES` (default 250 MiB), limits uploads to 100 files and one 4 KiB field, and returns 413 for oversized transfers. `DRIVE_DOWNLOAD_MAX_BYTES` defaults to 250 MiB and bounds both remote file bytes, total folder input bytes and ZIP output bytes, including streams that grow beyond their listed size. Folder file and directory counts use `FOLDER_DOWNLOAD_MAX_FILES` (default 750). `DRIVE_TRANSFER_MAX_CONCURRENCY` defaults to two uploads/downloads/previews; permits remain held until upstream work settles even after a caller disconnects. These are deliberate policy bounds and may reject previously accepted large transfers. Restore the prior verified release/configuration to roll back while preserving the strict host-pin requirement.

Vision provider model discovery requires the same read permission as chat. Outreach claims a draft durably as `sending` before invoking its email transport, so concurrent requests cannot send it twice. A failed/uncertain provider result becomes `delivery_unknown`; process termination can leave `sending`. An operator must reconcile the provider delivery state before any retry. Automatic retry is intentionally unavailable until provider idempotency and reconciliation are defined.

Vision upload policy permits one ingestion at a time per worker process, checks project ownership before reading the multipart body, and bounds intake to 128 MiB with a 60-second read deadline. A request contains at most 100 top-level files, 2,000 combined archive/direct entries, 128 MiB per file, and 256 MiB combined expanded content across all archives. These are deliberate memory policy bounds; split larger plan sets into separate uploads. Existing per-archive path, encryption and compression-ratio checks still apply. Scaling to multiple worker processes requires a shared admission-control budget.

The legacy Leads-to-Vision handoff remains unavailable (`503 HANDOFF_AUTH_NOT_CONFIGURED`) until its caller contract binds each project to a verified organization. A CRM capability and shared integration key alone do not establish that ownership. Restoring this workflow requires approved organization/role provisioning and a tested signed principal contract; do not use client-supplied organization headers or the default local organization.
